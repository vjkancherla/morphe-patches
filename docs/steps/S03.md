## How the check runs (S03)

- Rebuilds, re-patches, and ALWAYS installs the freshly patched build with `install -r`
  (data kept, switches survive) - a check can never bless an older build.
- Entry gate: the phone attached over adb and UNLOCKED (adb cannot clear the keyguard),
  and *Hide feeds* ON - found OFF once at entry and flipped through the stock home's menu,
  then re-verified on the switch itself.
- Then the gauntlet: V7 (top-bar search button opens search; Back exits, no feed, no
  crash), V9 (five Backs never reach the Home feed - a failure here is a STOP), V12 (cold
  external `r/soccer` link stays on top, no search over it), V13 (cold root link, no feed),
  V8 (the hide-nav patch coexists with the other hide patches in one run), V10 (resume
  from background shows no feed), V15 (rotation: no feed, no crash, pixel-diversity
  score recorded), V16's reachable routes (Home re-tap, Communities re-tap - the slot is
  absent on this phone, server state, variant recorded - and the Popular row guarded),
  V14 (*Hide Create* + *Hide feeds* together: search still lands, the bar is
  Home/Create-less, both toggles restored after), V19 (*Hide Inbox* hides both bar
  Inboxes, OFF restores them), then V20 LAST, and a final logcat sweep for hook failures
  and crashes across the whole run.

## The three harness lessons this step paid for

The first three runs each failed V7 with a different face, and all three were harness
facts, not product bugs - every fix is in `scripts/checks/S03.sh`, no product code touched:

1. **The ColorOS app-details sheet pops up between checks, not only during install.**
   "Installed / Version 2026.45.0 / 160 MB / Close" parked over the front window seconds
   after the install had already been blessed. And dismissing it has teeth: tapping Close
   may not land, and the BACK fallback can exit Reddit to the launcher instead of the
   sheet. `dismiss_overlays` now taps Close -> re-dumps -> requires the sheet gone -> BACK
   -> re-dumps -> requires gone -> **requires Reddit in front** (resuming the app if the
   launcher won, via the new `bring_reddit_front` helper) and fails loudly otherwise.
   `top_bar_search_button` also dismisses at point of use, before any state is read.
2. **The top bar's search control is `content-desc="search on Reddit"` - there is no plain
   `Search` node on this build.** The old `tap_node "Search"` silently matched nothing and
   never tapped, so the check failed with "no search page after the tap" while the phone
   never saw a tap. The check now taps the pill (with "Search" as fallback) and fails
   loudly if neither node exists. Verified live: the pill opens the search page.
3. **V14's state chain must be re-established, never assumed.** After the *Hide Create*
   toggle and `leave_settings`, the check now cold-starts, polls the search page with
   `wait_for_ui 'Search Reddit' 20`, fails explicitly if Back will not close it, and reads
   the Create-removal assertion only from the bar dump of that live chain. A stale
   variable can no longer stand in for the bar.

Also folded into the shared helpers: `open_morphe_entry` fails fast when the search page
will not close, and `cold_start` propagates a failed sheet dismissal.
