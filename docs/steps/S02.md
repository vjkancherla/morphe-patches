# S2 - Tapping Home stays off the feed; the setting OFF behaves stock

## In one sentence

Hooks 2-3 keep every internal "go to Home" on the empty start screen even when a route
re-selects Home without a tap, proven on the phone by the S02 device run (13/13), with the
setting OFF verified stock and the Guest mode untouched throughout.

## How it works

- Hook 2 - the cold start's `initial_tab` default read: when the launch carries no tab
  extra (every plain cold start), the Communities start tab is installed instead of Home.
- Hook 3 - the selection funnel (the presenter's re-selection path): any programmatic or
  repeated selection of Home is rewritten to the Communities tab, and the once-per-process
  search launch fires on its first attach. The already-selected branch the old build fell
  through is retired by the third amendment (hook 6, in S1's commit) - so repeated Home
  taps cannot land the bare blank Home page any more.
- Every hook call is verified where it claims to sit (read-back), and a miss fails the
  patch.
- The search launch is one shared, debounced helper (~1 s, once per process, failures
  logged) - never a crash, never a double-launch.

## How the check runs (S02)

- Rebuilds, re-patches, and ALWAYS installs the freshly patched build with `install -r`
  (data kept, the switch survives) - a check can never bless an older build.
- Feature ON: cold start opens search by itself (V5 re-run); a Home tap opens search and
  Back shows the Communities top bar over an empty page (V16 Home route).
- Feature OFF (the switch is driven through Morphe settings and verified on the switch
  itself): the stock Home feed renders (V17) and the menu's Popular row renders normally.
  This build's guest screens show content without classic vote/share a11y labels, so
  "renders normally" reads the screen's pixel diversity, not the dump's node labels.
- Then the switch goes back ON and the cold start lands search again - proving the toggle
  round-trip.

## Known device facts folded in

- After backing out of the cold-start search, the underlying blank screen (guarded
  `HomePagerScreen`) does NOT carry a Communities top bar; the top bar arrives through the
  Home-tap flow. S01 asserted the top bar only where it is true.
- The uiautomator tree carries every node's empty `text` attr ahead of its `content-desc`;
  a first-attribute matcher hides content-desc-only labels (the top bar's menu, the
  search hint). The check scans both attributes per node.
